# CI 门禁与走查红绿账（09-25）

来源：opencode v2 调研 3.7 第 3 条（工作安排第二节第 4 小节「之后可选」）。分支
`worktree-ci-fleet-2026-09-25`，从集成分支 `worktree-integration-2026-09-25`（72544dec）开。

## 用户拍板
- 不装每晚自动跑的定时器，整批走查手动跑（`python3 testkit/fleet.py`）。
- `tui/run.py` 里跟机器快慢有关的时间阈值顺手改成按状态 / 倍率判定。

## 改之前
- CI 的单测只跑 `cargo test --workspace --lib`：`tests/` 下起真 daemon、真渲染 worker 的两条集成测试
  （`daemon_reload`、`renderer_worker`）从来没在 CI 上跑过。
- 文件规模、层序、网页 i18n 三道只依赖标准库的门禁只在本机 `refactor-check.sh` 里跑。
- testkit 一个走查都不跑，也没有清单：哪些该绿、哪些早就红着，只在各会话的记忆里。

## 做法
- **CI**（`.github/workflows/ci.yml` 的 format-and-python）新增四步：文件规模（`--check --strict`）、层序、
  网页 i18n、走查红账。单测一步（`packaging/ci/run_tests.py`）`--lib` → `--tests`。
- **文件规模的 CI 严格模式**：「新增越红线文件」原来的判据是「上一个提交里没有这个文件」，CI 的干净检出里
  每个文件都在上一个提交里，那条在 CI 上恒不成立、等于没查。`--strict` 改成凡是基线里没有的越红线文件
  都判红（现在全仓没有越 2000 行的文件，严格模式照样绿）。
- **走查红绿账**：
  - `testkit/fleet.json` 登记 136 个离线、能自动判绿的走查：终端、网页（Playwright）、daemon/CLI/会话库、
    QQ（假 NapCat）与中转线（假 agy / 假 claude）四条车道。要真模型、真 kitty、音频、真人、事先起好的
    daemon、只量不判的不收，清单写在 `testkit/fleet.py` 文件头。
  - `testkit/fleet.py`：一个一个跑（每项一个全新的 MIYU_HOME、跑完留着查日志，端口固定在 18691–18695，同一时刻只跑一项），
    判定是退出码 + 没有少过的「N/M passed」+ 清单里写了 `pass` 的还得在输出里找到它（给只打印结论、
    不设退出码的那十几个走查）。账上该绿的红了当场复跑一次（AGENTS §8.5 的「复跑一次，第二次仍红才算问题」写进了
    脚本）。和 `known_red` 对账：新红（两次都红，退出码 1）/ 抖动（复跑绿，只报告）/ 旧红 / 红转绿（该从账上划掉）。
    产物在 `~/.cache/miyu-fleet/<时间>/`。
  - `known_red` 只减不增：CI 里 `--check --against-ref HEAD^`（PR 上 HEAD^ 就是目标分支）。
  - `testkit/mermaid/probe.py` 原来写死 `target/debug/miyu`，改成先认 `MIYU_BIN` / `BIN`，和别的走查同一个口径。
- **走查读到半帧**（集成走查撞出来的，main 上就有）：`lobby_lane` 的 `materialize_keeps_the_number` 偶发读到上一条
  车道的数（2.6k≠10.8k，改前 main 基线 1/5、活尾巴 2/5、集成 1/3）；建账时 `goal_hint` 截到的那一屏只有提示行、
  输入框和 footer 都还没画。根因在走查：pyte 不认同步块（`ESC[?2026h` … `l`），一帧从上往下画到一半就去判、去截屏。
  真终端按块整帧呈现，人看不到半帧。修在共用读屏函数里（`tui/run.py`）：
  - `frame_complete(sink)`：流是不是停在帧边界上（按流各记各的扫到哪，有的走查同时开两个 TUI）；
  - `drain_until` 与 `round26.wait_screen` 只在帧画完时判，返回时流就停在帧边界上；
  - `drain` 定时读完若停在一帧中间，再读到这一帧画完（最多 1 秒）。
  先在 `lobby_lane` 自己身上改（空闲时 8/8 绿），再收进共用函数、撤掉它那份（后一半核满载编译时 `goal_hint`、
  `lobby_lane` 各 3/3 绿）。
- **`tui/run.py` 的 item02**（AI 输出时一串鼠标事件会不会把键盘堵住）：原来要求那个字符 500ms 内回显。改成
  同一时刻先量一个不带鼠标事件的字符作基线，判「不超过基线的 10 倍（基线按 40ms 起算）」。堵队的实现是一个
  tick 只取一个事件，80 个事件是基线的几十倍；机器忙时两个数一起变慢，比值不动。run.py 里别的时间窗都是
  「多久之内出现」式的宽松期限，本来就是按状态判的，不动。
