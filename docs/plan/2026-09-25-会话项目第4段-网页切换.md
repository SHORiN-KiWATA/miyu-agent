## 改前

- 网页的会话接口（回合、上下文、待办等二十来个）只认 `kind == "user"`，子会话一律 404。
- 没有列子会话的 HTTP 接口，只有 IPC 的 `ListSubagentSessions`。
- 子会话 id 其实到得了浏览器：实时那条 `__subagent_session__<id>` 标记（`tool.progress`）、库里的
  `ToolFlowCall.child_session_id`。但网页一处都没用；标记还会在卡片的窥视那一行上闪一下
  （漏进 `parseSubagentEvent` 的 plain 分支）；DTO 把 `child_session_id` 丢了。

## 改了什么

### daemon
- `require_viewable_web_session`：子会话往上找到根会话，归属、人格、平台那几条闸落在根会话上；
  根会话你能看，它名下的子会话你就能看。回合、上下文、待办三个只读接口换成它。
- `GET /api/sessions/{id}/subagents`：和 IPC `ListSubagentSessions` 共用 `subagent_sessions_json`。
- 回合接口多带 `session_kind` 与 `parent`（`{session_id, name}`），网页据此挂「↑ 主会话」。
- 工具调用 DTO 带上 `child_session_id`（回看时卡片认得出子会话）。
- 子代理会话的第一轮在回合接口里标 `from_parent`（只在翻到会话开头那一页时；判据同终端，
  `turn_from_parent`）。

### 网页（新文件 `web/subagents.js`，app.js 只加几处钩子）
- 子代理卡片认子会话：实时那条标记（认出来就吃掉，不再漏进窥视）、回看的 `child_session_id`、
  结果里的 `session …`（和 Rust 的 `subagent_session_of_output` 同一个认法）。
- 认出来了，点卡片抬头就打开子会话，不再原地展开。后台子代理刚派出去时子会话还没建，卡片照旧。
- 在子会话里，输入框上方挂「↑ 主会话 · 名字」，点它回去。
- 子会话第一句画成「来自主会话的任务」那一块（借跨会话消息那一块的样子，换抬头和图标），不是
  用户气泡——和终端一样。

### 顺手的两处网页修复（09-25 用户拍板并进这一段）
- 实时卡片漏字：daemon 的老标记中继发 `__subagent_metric__`（词元）、`__subtool_preparing__` 等，网页只认
  直连模式发的 `__subagent_stats__`，认不出的掉进 plain 分支、原样写进窥视那一行（闪一下就被下一条盖掉）。
  现在认 `__subagent_metric__`，把词元写进卡片上的小标（daemon 模式下这个小标原来一直空着）；其余
  `__sub…__` 一律吞掉。输入框的「累计」不接：那套 done/基线是照直连模式写的，接上可能重复计，留给 B 组。
- `buildSubagentBrief` 的局部变量 `t` 遮住了翻译函数 `t()`：子代理有任务内容、标题却是空的时，
  `t("任务 prompt")` 抛 TypeError，卡片画不出来（71acea59 双语改造带进来的）。局部变量改名。

## 删除清单（待用户拍板，拍板之前一行不删）

### 核查结论
设计文档 §4 列的东西，**没有一项现在只剩浮层在用**。daemon 还在把子会话的事件翻成老标记
（`subagent_host.rs` 的 `relay_child_events`），这条标记流喂着：
- 终端时间线上子代理那一行的窥视和词元（秒数走通用的工具计时，不靠它）；
- 网页卡片的窥视。网页在 daemon 模式下的词元一直没喂上：它只认 `__subagent_stats__`，那只有
  直连模式的老 runner 发。反过来 daemon 发的 `__subagent_metric__` 网页不认，原样漏进窥视那一行
  （09-25 已修，见上面「顺手的两处网页修复」）；
- 后台子代理的任务日志（模型 `job(action=status)` 读的就是它）、任务条上的词元、网页任务面板；
- 前台子代理跑着时 `child_session_id` 的唯一来源（`tool_report.rs` 从 `__subagent_session__`
  标记里取）。

直连模式（没有 daemon）还整套跑老的进程内 runner。
