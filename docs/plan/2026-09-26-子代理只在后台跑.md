# 子代理只在后台跑（09-26 施工单）

来源：用户 09-26「我希望把子代理改成只有后台运行。不前台运行了。」摸底见记忆
`miyu-subagent-bg-only-2026-09-26`（Explore 子代理只读摸底，文件位置在那里）。

## 用户拍板（09-26）
- 只后台，不前台。
- 结果回主会话：**每个子代理跑完各叫醒一次**（沿用现在后台的投递：父会话闲着就起唤醒轮，
  跑着就排进这一轮）。
- `/goal`：有子代理在后台跑就不续轮，等报告回来再续。
- 一次性命令（`miyu "…"`、`miyu ask`、JSON 输出）：等整棵子树跑完、带结论再退出。
- QQ（只有管理员回合有子代理）：**合成一份发**；账号掉线时留着，连上再发。
- 我报的默认项（用户没反对）：并发仍限 4、多的排队；父回合跑着时 Ctrl+C 连它这一轮派出的子
  代理一起停；修「取消回合把已排队的报告一起丢」；老回合的前台输出照旧能回放。

## 开工前又定的四点（09-26）
1. **没有 daemon 的两条路**（直连调试模式 `MIYU_DIRECT=1`、不经 daemon 的 `miyu tool-call`）：照旧前台
   ——没人能把模型叫醒，只后台的话结果回不来。`background` 参数只有这条路还认，工具说明里不写了。
2. **`/goal` 续轮提示**：只补一句「派了子代理就结束这一轮，报告回来会接着来」，原句一字不动。
3. **QQ 掉线时留着的报告**：存进会话库（daemon 重启也不丢）。
4. **并发上限**：按父会话算（同一个会话同时最多 4 个，别的会话不受影响）。

## 施工步骤（一步一提交，每步单测 + 走查）

### 一、引擎只留后台
- `tools/subagent/mod.rs::run_via_host`：不再看 `background` 参数，一律走
  `jobs::spawn_background_subagent`；续已有子会话同理（跑着的排进去、没跑的后台新起一轮）。
- 回执带子会话 id：子会话先建好再 detach（`SubagentHostPort::spawn` 拆出「建会话」一步），回执
  JSON 加 `session_id`，时间线上那一步点得进子会话（现在后台回执不带，要等任务里才建）。
- 工具说明 `src/tools/descriptions/subagent.json`：去掉「returns one final message」「Use
  background=true for long tasks」，写成「派出去在后台跑，跑完带着结论叫醒你；派完就结束这一轮，
  别轮询」；`background` 从 schema 删掉（老回合里的这个参数照旧能解析、忽略）。改完跑
  token 预算测试与 `request_shape_probe`：只该变 subagent 这一件（计划内的一次冷启动）。
- 并发：每个父会话一个信号量（`tools.subagent_concurrency`，默认 4），镜像任务里先拿许可再起子
  会话；排着的任务在任务条上写「排队」。

### 二、daemon 这边
- `/goal` 闸（`web/goal_driver.rs`）：会话名下有没收尾的子代理任务就不续轮；唤醒轮结束照旧踢一下
  驱动器。
- 一次性命令：回合结束后看这条会话（整棵树）还有没有在跑的子代理，有就跟着下一轮唤醒输出，直到
  会话闲下来、没有任务，再收摊（`discard_ephemeral_session` 之前）。JSON 输出带最终结论。
- QQ：同一个 QQ 会话同一轮派出的子代理，最后一个跑完时合成一份报告起一轮（每份报告照旧落库）；
  账号没连上就留着，连上后补发。
- 父回合 Ctrl+C：取消一轮时，连这一轮派出的子代理任务一起停（整支，含孙代理，走
  `stop_subagent_subtree`）。镜像任务记下派它的轮号。
- 取消回合不丢报告：`web/turns/task.rs::drop_cancelled_queue` 只撤用户排的话，后台任务报告留下、
  这一轮结束后照常投递。

### 三、界面
- 子代理那一步：回执带了子会话 id，点得进子会话（终端、网页）。
- 只为前台存在的显示（子代理步骤的实时词元 / 用时、Σ 实时加数、`subagent.progress` 一串等）：
  删之前列清单等拍板（`confirm-before-deleting-redundancy`）；老回合回放要用的解析器都留着。

### 四、测试与走查
- 前台专测（约 30 条）改成后台语义或删（删的进清单）。
- testkit：`STUB_SUBAGENT` 触发的走查按后台语义过一遍（subagent_visit、strip_tree、turn_end_notice、
  stop_from_main、bg_visit*、tui/run.py 等）。
- 新走查：派完主回合立刻结束、报告叫醒；`/goal` 等报告；一次性命令等子树；QQ 合并与掉线留存（假
  NapCat）；父回合 Ctrl+C 连带停；取消回合不丢报告。
- 收尾：refactor-check 五道 + `request_shape_probe` + 红绿账全量。

## 风险
- 模型行为：派完要结束这一轮。工具说明和回执里写清，真模型走一遍看它会不会空转查状态。
- 每份报告至少一次整段上下文的请求（用户选了各自叫醒）。
- 改动面大：一步一提交，每步都能单独退回。
