# 会话切换、删除、回合中压缩（09-25）

来源：用户验收集成分支时实测七件事——任务条的 `›` 顶掉转轮、切会话不顺、子会话之间不能直接切、
从子会话回来 footer 上下文从几十 k 掉到 13k、主会话「异常消失」、`/compact` 报 busy、`/session`
里 Ctrl+D 删着删着面板退出。分支 `worktree-session-ux-2026-09-25`，从集成分支 9fc063e1 开。

## 用户拍板
- 正在跑的会话（它自己或它的子代理在跑）在 `/session` 里要按两下 Ctrl+D，闲着的照 09-20 一按就删。
- 回合中的 `/compact`「像 followup 消息一样排队」。
- 子会话的任务条列出兄弟，点兄弟横着切。
- footer 用守护进程报的实时数。
- 不恢复那条被删的主会话（其余几条是用户自己删的）。

## 根因

### 主会话「异常消失」与「删着删着退出列表」是同一个毛病
取证：删之前一刻的库从 WAL 回溯出来（`~/.cache/miyu-session-loss/`），删除落在 20:22:22 的一次提交里；
痕迹和「删一条正在跑的会话」逐条对得上。沙箱走查 `testkit/tui/session_ux_probe.py` 复现。
- 守护进程删会话的顺序是「先停回合 → 拆子代理树 → 最后才占住会话去删」。拆后台子代理会给父会话回一条
  「后台任务报告」，它当场起一轮把会话占住，最后那一步报 busy：回合被掐、子代理全删、会话本身还在，
  面板一声不响地关了（`outcome.is_none()` → 不重开）。重开面板时光标默认停在当前会话上，再按一下就真删了。
- 面板对正在跑的会话不设防，而回合中的 `/delete` 是被拦的——同一件事两个口径。
- 从子会话里开 `/session`：子会话不进列表，没有一行带「*」，光标落在第 0 行，而那往往就是正跑着的主会话。

### `/compact` 报 busy
压缩要先占住会话（`reserve_admin_for_session`），会话里有回合就回 409「Miyu is busy with another
operation」。客户端知道回合在跑时会先拦下并说明原因；用户看到 busy，是客户端以为闲着、守护进程那边
其实有一轮在跑（上面那条后台报告起的一轮就是）。挂着子代理等十几分钟的回合，这段时间压不了。

### 回来后 footer 上下文变 13k
回到正跑着的会话时，footer 取守护进程的快照。不是守护进程「当前会话」的，快照按库里存的回合现估；
正在跑的那一轮要跑完才落库，于是只剩系统提示词加前几轮。Σ 同理（走查里 99.0k → 25.5k）。下一次用量
事件来了才纠正，挂着子代理等的时候可能要好几分钟。就算是守护进程的当前会话，回合中途快照里的数也要
等回合结束才更新。

### 切换不顺
逐帧记录（`testkit/tui/session_switch_frames.py`）：每切一次，终端上先后出现 6–8 个中间画面——转轮
熄掉、时间线撤掉、整屏清到只剩四五行、回放、回主会话时再过约 0.2 秒才把正在跑的那一轮挂回来、转轮才
出现；每次清两次整屏；外加一条「已切换到会话」提示；footer 的数跳一下。

### 子会话之间不能直接切 / `›` 顶掉转轮
子会话的任务条只列「↑ 主会话」；方向键停着的那一行，`›` 画在转轮那一格上。

## 做法
- **删除先占住**（`web/sessions/delete.rs`，从 `session_cmds.rs` 搬出来）：一开始就占一个「删除预约」
  （不要求会话闲着，只挡新回合：排队消息、后台报告、目标续轮都认 `admin_blocks_session`），再停回合、
  拆树、换兜底会话、删行。占不住（别的管理操作占着）就原样报错，什么都不碰；回合停不下来也什么都不拆。
- **面板**（`session_picker.rs`）：会话列表每行带 `running`（它自己或子代理在跑，`sessions_with_running_trees`），
  这种行第一下 Ctrl+D 只把那一行换成提醒，再按一下才删，按别的键作废。删不掉的原因显示在面板里、面板不关；
  删掉自己待着的那条先落到兜底会话上，再在原位把面板开回来（空闲路 `SessionPickOutcome::Fallback`，
  回合中那条路经 `LiveReplTail::reopen_session_picker`）。从子会话里开 `/session`，访问栈的根算「当前」。
- **回合中压缩排队**：`slash_commands::during_turn` 给 `/compact` 新档 `Queue`。守护进程按会话存一份
  `TurnCompactRequest`（`ManagerState::compact_requests`），回合的控制句柄挂的就是它；会话里有回合时
  IPC / 网页的压缩不再回 busy，而是立起请求、回 `queued`。回合循环在接插话的两处取走它：一批工具跑完
  之后压掉本轮之前的历史、拼回本轮活尾巴前面接着跑（和溢出恢复共用 `splice_compacted_prefix`，前缀变了
  顺手清掉 Responses 续传链）；模型要收尾时只压库。这一轮没走到这两处就退场的，由 `compact_queue` 的
  驱动器在回合退场后补压。终端排队区挂一行「/compact 排队中」，压缩一开始或这一轮结束就撤。
- **实时数**：事件映射器转发 `RoundUsage` 时，按会话记下最近一次请求的上下文（输入 + 输出）和会话实时
  累计（`ManagerState::live_turns`），回合全部退场就清；两处快照和 `/session` 列表遇到正在跑的会话就用它。
- **切换一帧画完**：全屏下加「攒帧」（`tail/update.rs`）——开着的时候最外层同步块收尾不写出去，续在
  内存里，放行时整段作一帧。切换开始（回合因切走而暂停、`switch_to_session`、`present_visit`）时打开；
  目标会话没有在跑的回合就在画完时放行，有的话等跟随循环补发的那一阵画完（40ms 没有新帧）再放行；
  回到空闲读输入前兜底放行；最多攒 500ms。进出子会话不再弹「已切换到会话」。
- **任务条**：每行前面留两列，`›` 放在那里，转轮照常；在子会话里，父会话下面列兄弟（轮询线程按父会话再
  拉一份，刚切进来时用父会话那份子代理列表垫上），当前这条标 `●`，点兄弟横着切（访问栈不压新层）。
