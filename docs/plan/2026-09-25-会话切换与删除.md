# 会话切换、删除、回合中压缩（09-25）

来源：用户验收集成分支时实测七件事——任务条的 `›` 顶掉转轮、切会话不顺、子会话之间不能直接切、
从子会话回来 footer 上下文从几十 k 掉到 13k、主会话「异常消失」、`/compact` 报 busy、`/session`
里 Ctrl+D 删着删着面板退出。分支 `worktree-session-ux-2026-09-25`，从集成分支 9fc063e1 开。

## 用户拍板
- 正在跑的会话（它自己或它的子代理在跑）在 `/session` 里要按两下 Ctrl+D，闲着的照 09-20 一按就删。
- 回合中的 `/compact`「像 followup 消息一样排队」。
- 子会话的任务条列出兄弟，点兄弟横着切。
- footer 用守护进程报的实时数。
- 不恢复那条被删的主会话（其余几条是用户自己删的）。

## 根因

### 主会话「异常消失」与「删着删着退出列表」是同一个毛病
取证：删之前一刻的库从 WAL 回溯出来（`~/.cache/miyu-session-loss/`），删除落在 20:22:22 的一次提交里；
痕迹和「删一条正在跑的会话」逐条对得上。沙箱走查 `testkit/tui/session_ux_probe.py` 复现。
- 守护进程删会话的顺序是「先停回合 → 拆子代理树 → 最后才占住会话去删」。拆后台子代理会给父会话回一条
  「后台任务报告」，它当场起一轮把会话占住，最后那一步报 busy：回合被掐、子代理全删、会话本身还在，
  面板一声不响地关了（`outcome.is_none()` → 不重开）。重开面板时光标默认停在当前会话上，再按一下就真删了。
- 面板对正在跑的会话不设防，而回合中的 `/delete` 是被拦的——同一件事两个口径。
- 从子会话里开 `/session`：子会话不进列表，没有一行带「*」，光标落在第 0 行，而那往往就是正跑着的主会话。

### `/compact` 报 busy
压缩要先占住会话（`reserve_admin_for_session`），会话里有回合就回 409「Miyu is busy with another
operation」。客户端知道回合在跑时会先拦下并说明原因；用户看到 busy，是客户端以为闲着、守护进程那边
其实有一轮在跑（上面那条后台报告起的一轮就是）。挂着子代理等十几分钟的回合，这段时间压不了。

### 回来后 footer 上下文变 13k
回到正跑着的会话时，footer 取守护进程的快照。不是守护进程「当前会话」的，快照按库里存的回合现估；
正在跑的那一轮要跑完才落库，于是只剩系统提示词加前几轮。Σ 同理（走查里 99.0k → 25.5k）。下一次用量
事件来了才纠正，挂着子代理等的时候可能要好几分钟。就算是守护进程的当前会话，回合中途快照里的数也要
等回合结束才更新。

### 切换不顺
逐帧记录（`testkit/tui/session_switch_frames.py`）：每切一次，终端上先后出现 6–8 个中间画面——转轮
熄掉、时间线撤掉、整屏清到只剩四五行、回放、回主会话时再过约 0.2 秒才把正在跑的那一轮挂回来、转轮才
出现；每次清两次整屏；外加一条「已切换到会话」提示；footer 的数跳一下。

### 子会话之间不能直接切 / `›` 顶掉转轮
子会话的任务条只列「↑ 主会话」；方向键停着的那一行，`›` 画在转轮那一格上。

## 做法
- **删除先占住**（`web/sessions/delete.rs`，从 `session_cmds.rs` 搬出来）：一开始就占一个「删除预约」
  （不要求会话闲着，只挡新回合：排队消息、后台报告、目标续轮都认 `admin_blocks_session`），再停回合、
  拆树、换兜底会话、删行。占不住（别的管理操作占着）就原样报错，什么都不碰；回合停不下来也什么都不拆。
- **面板**（`session_picker.rs`）：会话列表每行带 `running`（它自己或子代理在跑，`sessions_with_running_trees`），
  这种行第一下 Ctrl+D 只把那一行换成提醒，再按一下才删，按别的键作废。删不掉的原因显示在面板里、面板不关；
  删掉自己待着的那条先落到兜底会话上，再在原位把面板开回来（空闲路 `SessionPickOutcome::Fallback`，
  回合中那条路经 `LiveReplTail::reopen_session_picker`）。从子会话里开 `/session`，访问栈的根算「当前」。
- **回合中压缩排队**：`slash_commands::during_turn` 给 `/compact` 新档 `Queue`。守护进程按会话存一份
  `TurnCompactRequest`（`ManagerState::compact_requests`），回合的控制句柄挂的就是它；会话里有回合时
  IPC / 网页的压缩不再回 busy，而是立起请求、回 `queued`。回合循环在接插话的两处取走它：一批工具跑完
  之后压掉本轮之前的历史、拼回本轮活尾巴前面接着跑（和溢出恢复共用 `splice_compacted_prefix`，前缀变了
  顺手清掉 Responses 续传链）；模型要收尾时只压库。这一轮没走到这两处就退场的，由 `compact_queue` 的
  驱动器在回合退场后补压。终端排队区挂一行「/compact 排队中」，压缩一开始或这一轮结束就撤。
- **实时数**：事件映射器转发 `RoundUsage` 时，按会话记下最近一次请求的上下文（输入 + 输出）和会话实时
  累计（`ManagerState::live_turns`），回合全部退场就清；两处快照和 `/session` 列表遇到正在跑的会话就用它。
- **切换一帧画完**：全屏下加「攒帧」（`tail/update.rs`）——开着的时候最外层同步块收尾不写出去，续在
  内存里，放行时整段作一帧。切换开始（回合因切走而暂停、`switch_to_session`、`present_visit`）时打开；
  目标会话没有在跑的回合就在画完时放行，有的话等跟随循环补发的那一阵画完（40ms 没有新帧）再放行；
  回到空闲读输入前兜底放行；最多攒 500ms。进出子会话不再弹「已切换到会话」。
- **任务条**：每行前面留两列，`›` 放在那里，转轮照常；在子会话里，父会话下面列兄弟（轮询线程按父会话再
  拉一份，刚切进来时用父会话那份子代理列表垫上），当前这条标 `●`，点兄弟横着切（访问栈不压新层）。

## 09-26 验收时的四件（用户反馈）

### 从子代理点「↑ 主会话」回来后 TUI 不能交互（输入框里是 `^[[27u`）
根因：raw 模式的交接标记坏了。主会话自己这一轮还在说时点进子代理，回合循环（`one_shot`）切走前把 raw
「交接」出去（`raw_mode_handoff = true`，终端留在 raw 里等下一段认领）；子代理那一轮由事件泵
（`wake::follow_wake_run`）跟着看，可它从不认交接，自己又 `LiveRawMode::start()` 一把（键盘增强再推一层）。
点「↑ 主会话」时事件泵那把守卫一放：raw 关掉、弹掉一层键盘增强，交接标记却还立着。回到已经说完的主会话，
输入循环按标记「认领」——不开 raw——终端停在回显模式、kitty 键盘协议还开着：Esc 回显成 `^[[27u`，打的
字只有回显，TUI 一个键也收不到（主线程在 epoll 里等，看着像卡死）。
之前复现不出来，是走查的三种回法都没走「主会话自己这一轮还在说时点进去」这条路，而且「打几个字看得见」
分不出真输入和回显。新走查 `visit_back_probe.py` 的 `ENTER_MIDTURN=1` 走这条路，并用 PTY 主端的 TCGETS
读从端的 ICANON/ECHO 判终端在不在 raw 里：改前 `raw_after_back=false`，改后 true。
做法：
- 读键的几段（输入循环、回合循环、事件泵、直连回合）一律经 `LiveReplTail::take_raw_guard` 拿守卫：有交接
  就认领，没有才新开；交接却发现终端是 cooked 的（有人中途放掉了），就地把 raw 补开，键盘增强按「还压着」
  接管，不再推一层；
- 事件泵切走的几个口子（点任务条会话行、回合中面板挑了别的会话、回合中要分离的命令）和 `one_shot` 一样
  把 raw 交出去，切换那几百毫秒终端不回显；点会话行切走时也攒帧。

### 切回来那一下状态行消失一瞬间
根因：切会话分两步改轮询那份（先换访问的父会话、再换会话），中间那一步按半新半旧的范围摘任务，退回主会话
时把主会话自己的任务先摘掉了；兄弟表、子代理表也在切换时清空，要等下一轮轮询（约 1 秒）才补回来。
做法：轮询那份按会话存子代理表（`SharedJobsFeed::children`，访问路径上的都留着），会话和访问路径一起换
（`set_scope`）、一起按新范围摘任务（整棵树的任务都留着：树根是主会话）；切进切出之后当场拉一份这一段的
子代理表，和切换画面同一帧画出来。

### 任务条改成树（照 Claude Code，用户拍板）
- 子代理空心 `○`，正在看的实心 `●`，后台命令照旧转轮；
- 第一层只列这条会话自己的子代理和命令，名下还在跑的（孙代理、这一支的后台命令，daemon 在
  `ListSubagentSessions` 每行给 `running_descendants`）收成「开发中（+3）」，原来挂 `↳` 列在主会话任务条上
  的后代任务不再单列；
- 在子代理会话里：`○ 主会话` 钉在最上面；下面是父会话的子代理，正在看的这条展开，它的子代理和命令用
  `├`/`└` 挂在它下面；父会话自己的命令也在第一层；
- 露不下五行时，钉住的那行不动，其余停在露出正在看的这条和挂在它下面的地方，方向键挪的时候跟着走；
- 行怎么排在 `repl/strip_tree.rs`，行本身在 `repl/strip.rs`（`StripItem`）。

### 子代理里 Ctrl+C 停不下孙代理
根因：切进子代理后跟着它那一轮看的是事件泵，Ctrl+C 在那里只「脱离」（那条路是给后台唤醒轮定的），子代理
在 daemon 里照跑；就算停了它这一轮，后台孙代理本来也不跟着停。
做法（用户拍板「连同它名下的一起停」、终端网页一个规矩）：事件泵在子代理会话里按 Ctrl+C 发取消；daemon
在子代理会话里停一轮（IPC / 网页停止都走 `cancel_run_and_disarm_goal`）时另起 `stop_subagent_subtree`：先停
它自己的后台任务（含孙代理的镜像任务，记成「已停止」的任务收尾不叫醒它），再由深到浅停孙代理的轮和命令，
没到终态的记成被打断；闲着等后台时按 Ctrl+C（`StopSessionJobs`）同样整支停，它自己也记成被打断，等它的
主会话照常收到汇报。主会话的停止不变。

### 子代理里停下之后 Σ「往回掉」（验收时顺带发现，用户：一起处理）
不是打断丢账：打断那一轮的用量照记（`interrupt_turn_with_usage`，09-23 起就有），停下之后那个数才是对的。
根因在跟着看的那一阵算多了：09-25 起会话快照带 daemon 的实时数，切进一条回合正跑着的会话时，快照里的 Σ
已经含本回合至今；footer 的逐请求刷新是「快照 + 本回合」，又加一遍——跟着看时虚高，回合一停按库里的数重读，
看着就是往回掉（走查：子代理里 900，停下 750，750 = 子代理 450 + 两个孙代理各 150）。
做法：逐请求刷新直接取 daemon 随这次请求报的会话累计（`chat.round_usage` 本来就带，网页一直用它），不再在
快照上叠加。连带两处：跑完的前台子代理那份实时加数原来要到回合收尾才撤，改取绝对值后会和会话累计重复——
改成它跑完先留着、下一次请求报会话累计时再撤（`absorb_settled_subagents`），不闪也不重；每次刷新时实时加数
原来跟着基线快照退回旧值，Σ 往下闪一下，现在保住当下的。
验证：`cli/tests/round_usage.rs` 3 条（挂上在跑的回合不算两遍、刷新保住子代理那份加数，改前两条红；自己起的轮
照旧是守卫）、渲染器 1 条；`strip_tree.py` 加「Σ 停下不回掉」：450 → 750（改前 900 → 750）。

### 大文件编辑的 diff 算成整份替换（用户截图：`+1269 -1285`）
编辑工具的补丁预览用整张 LCS 表逐行比对，两边行数一乘过 25 万（各五百来行）就放弃、整份算成删了再加
（07-12 起就有，`fc60fe4a`）；时间线抬头的 `+N -M`（09-17）和点开的 diff 都读它，所以五百行以下的文件一直是对的，
一千多行的文件改一处就露馅。模型那边不受影响（工具结果只有 ok 和路径）。
做法（用户拍板精确差分）：`tools/line_diff.rs`——先剥首尾相同行，中间用 Myers 差分，耗时随改动量涨、与文件大小
无关，不加依赖；改动超过两千行才退回把中间那段整段替换。验证：`line_diff` 4 条 + `patch_preview` 1 条（一千三百行
改一行是 `+1 -1`、隔得很远的三处只数三处、整段重写照样还原得回来；摘掉换算法这一步前三条红）。

### 切到孙代理任务条变样、切完光标回输入框（用户验收截图）
- 树根原来跟着「回去的那一条」走：在子代理里是主会话，切到孙代理就变成了子代理（第一行「上一层」），整棵树
  缩成两行。用户要的是同一棵树、只挪实心圆。改成树根一直是主会话：访问路径上每一层都展开（路上的空心、正在看的
  实心），路以外的折起来带（+N）；每一行带着「切过去之后的访问栈」，任务条上往下、往上、横着切都是一个
  `StripAction::Go { session_id, path }`（原来的下切、横切、回去三种合一，`/back` 照旧一层层退）。轮询和切换时
  都按整条访问路径拉子代理表、留任务。
- 在任务条上回车切会话，原来先把光标收回输入框。现在光标留在任务条上，切完停在切过去的那一条
  （`apply_strip_refocus`）；回到主会话（顶层没有主会话那一行）就停在刚才待着的那一条。
- 验证：`strip_sessions.rs` 新增「切到孙代理还是同一棵树」「顶层点进去访问栈是主会话」，`strip_navigation.rs`
  新增「光标跟着切过去的那一条」；`strip_tree.py` 加方向键切孙代理、再切回子代理五项，22/22。
