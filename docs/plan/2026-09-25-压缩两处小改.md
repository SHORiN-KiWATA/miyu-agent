# 压缩两处小改：摘要结构校验、隔离路径补工具流（09-25）

来源：opencode v2 调研 3.2 第 1、2 条（工作安排第二节第 4 小节「之后可选」）。分支
`worktree-compact-checks-2026-09-25`，从集成分支 `worktree-integration-2026-09-25`（72544dec）开。

## 改之前
1. **摘要只判空。** fork 摘要带着完整的人格 system 发出去，模型偶尔顺着对话聊下去；那段正文会被当成摘要
   落库，折叠掉的历史从此只剩一句闲聊（`compact.rs` fork 与隔离两条路径都只查 `trim().is_empty()`）。
2. **隔离摘要看不到工具。** `turns_to_text` 只拼用户、助手、思考和 `tool_reports`，而 `tool_reports` 早就
   几乎为空，`tool_flow` 不在里面。fork 失败、关掉缓存复用、溢出兜底都走这条路径——开发会话在这条路径上
   压一次，命令输出和报错全丢。

## 做法
- `agent/compact_structure.rs`：模板的 `## ` 标题（从当前生效的模板里读，小写比较，容忍加粗和冒号）至少命中
  两个才算摘要；模板里不足两个标题就不校验（`MIYU_COMPACT_PROMPT_FILE` 换成无结构底稿时）。
- fork 路径：不合格就在同一个前缀后面追加「上一条回复 + 一句纠正」再要一次（前缀缓存照吃），还不合格交给
  隔离路径。
- 隔离路径：不合格按失败处理，走已有的「重试一次 → 自动压缩机械兜底 / 手动 `/compact` 报错」。
- 模板不动（`src/prompts/compact.md` 是实测敏感区）。纠正句是英文短句，只在不合格时出现。
- `agent/compact_transcript.rs`（`turns_to_text` / `turn_to_text` / 截断从 `compact.rs` 搬过来，
  compact.rs 1229 → 1158 行）：每个工具轮写这一轮的正文、思考（截 2000）、`[Tool call: 名字 {键名} (N keys)]`
  和截到 2000 字的 `[Tool result: …]`。防注入沿用 compact-plan Phase 3：参数值不进摘要器，只有真正的用户
  消息写成 `User:`。
- 插话的位置：按活体顺序记了轮间消息的 flow（`interleaved`）把插话放回它当时的位置；纯文本插话按正文认、带图
  的按排队消息 id 认；插话的瞬态尾巴、goal 通知是注入的上下文块，不写。老记录照旧排在工具轮前面。
- 中转线的 remote 轮照旧不进（和 fork 前缀同一个口径，它碰过的文件由 footprint 兜着）。

## 口径依据
- 本机现存的 5 份摘要（两份库备份里；活库 db+wal+shm 拷副本查过，一份都没有）全部保留英文九节标题，
  9–10 个 `## ` 行，所以「至少两个模板标题」不会误伤正常摘要。
- 两个而不是一个（opencode 是一个）：闲聊里碰巧写出一个模板标题的可能比两个大；两个是「确实照着结构写了」的
  最低信号。截在第一节就停的摘要也会被挡下重试。

## 测具配套

「context summarization assistant」）就回一份两节摘要：`testkit/repl-smoke/stub_llm.py`（TUI 走查共用）、
`testkit/cli/stub_llm.py`、`testkit/webui-fixes/stub_reasoning.py`、`testkit/compact-concurrency/stub.py`
