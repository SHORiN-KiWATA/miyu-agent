# MCP 常驻连接与服务器说明（09-25）

来源：opencode v2 调研 3.6 第 4 条（09-03 搁置过，这次重启），工作安排第二节第 3 小节。分支
`worktree-mcp-persistent-2026-09-25`，从 main 8c18c5d5 开（说明放系统提示词，不依赖指令源分支）。

## 现状（改之前）
- 每调一次 MCP 工具就新起一个服务器进程、用完就杀：浏览器、数据库这类有状态的服务器什么都记不住。
- 握手时服务器给的使用说明（`instructions`）整个丢掉。
- 服务器进程从不进沙盒、跑在 daemon 的目录里；成员会话也拿得到 MCP 工具，能借它碰到沙盒外的东西（读代码得出，
  本次沙盒用例坐实了修前的形状）。
- 另有四个问题：
  - 回合取消或外层超时时服务器进程泄漏；
  - 只杀直接子进程，npx / uvx / 浏览器的孙进程留成孤儿；
  - 改配置后第一次建注册表要现场列工具，actor 线程同步干等（最多 20 秒），别的会话跟着卡；
  - 服务器 stderr 整个丢掉，出事没法查。

## 用户拍板（四项全照推荐）
1. 按「服务器 + 会话 + 沙盒」各一份常驻进程；空闲 10 分钟回收，全机最多 8 个，满了退回每次新起。
2. 服务器按调用方的沙盒关进去；属主可给单个服务器配 `sandbox = "none"` 放开，成员永远不放开；个别要写沙盒外的
   服务器在配置里额外放行（`sandbox_writable`）。
3. 服务器说明放系统提示词（Claude Code 的做法，符合 AGENTS §1.4「指令放 system 侧」）。
4. 现存四个问题一起修。

另按推荐默认做、没单独问的：并发调用按请求 id 分发；超时只撤那一个请求，连着两次换进程；工具调用不自动重试；
崩了下次重起并注明；改配置只收变了的；非 daemon 维持每次新起。

## 做法
- `tools/mcp.rs` 拆成目录（见 `docs/interfaces/mcp-client.md` 的模块表）。
- 连接（`connection.rs`）：tokio 子进程、单独成组；按 id 分发、可并发；回 ping；超时 / 调用方撤了发
  `notifications/cancelled`；stderr 留尾巴；收进程关 stdin → SIGTERM → SIGKILL，最后整组再扫一遍。
- 专用线程（`runtime.rs`）：子进程与读写都在 `miyu-mcp` 线程上；调用方在自己的 runtime 里等，撤了那边跟着撤。
- 连接池（`pool.rs`）：钥匙、回收、上限、崩溃暂停、超时换进程、会话 / 配置 / 关停三处回收（见接口文档）。
  daemon 里 `forget_session_processes` 把中转线续传映射与 MCP 一起忘，五处调用点收成一处。
- 沙盒：`sandbox::confine_with`（按给定策略约束，不读任务上的那一份）；`SandboxPolicy.member`（成员策略，
  属主给单件工具开的口子对它无效）；`McpServerConfig` 加 `sandbox` / `sandbox_writable` / `persistent`
  （默认值不写进配置文件，网页对话框同样取默认就删键）。
- 说明（`instructions.rs`）：系统提示词最末尾 `<mcp-server-instructions>`，只带这一轮工具面里还有工具的服务器，
  转义、每家 2000 字、合计 6000 字。没配 MCP 时请求字节一个不变。
- 预取（`listing::prefetch`）：回合开始前异步列好缺的，actor 等的时候照样干别的。

## 行为变化（要写进发布说明）
- 属主会话默认开着沙盒（09-23 起），MCP 服务器进程从此也关在里面：服务器要写沙盒外的地方（浏览器缓存、自己的
  配置目录）会被拒，要在服务器配置里加 `sandbox_writable`，或者（仅属主）`sandbox = "none"`。
- 服务器进程的工作目录从 daemon 的目录换成这一轮的工作区。
- 同一会话里 MCP 服务器进程常驻 10 分钟，删会话 / 清空会话 / 改配置时收掉。

## 验证
- `cargo test -p miyu-engine --lib tools::mcp`：24 条。
  - 常驻：状态按会话保持；无会话、关了常驻时每次新起；崩溃后重起并注明；回服务器的 ping；清空会话连孙进程
    一起收掉；连着两次超时换进程；改配置只收变了的。
  - 说明：进系统提示词、按工具面带、转义。
  - 沙盒：沙盒里写不出去、属主放开能写、成员配了 `none` 照样写不出去（Linux Landlock 实测）。
  - 清单：缓存、并行、预取。
- 端到端 `testkit/mcp-persistent/run.py`（隔离 daemon + 专用桩模型 + 有状态假服务器）：本分支 5/5；main 2/5——
  main 上三次调用各起一个进程、计数都是 1，没有说明，删会话前进程早就没了。
- `request_shape_probe` 五张脸与 main 逐字节相同（没配 MCP 时系统提示词、工具面零变化）。
- 全工作区单测：根包 476、base 388、core 597、engine 589、hosts 892 全绿。

## 已知局限
- 列举工具的那一次进程不带会话，照旧不进沙盒（只握手、问清单，没有调用方输入）。
- 没做：HTTP / SSE transport、`tools/list_changed` 通知（服务器中途改清单要等下次改配置或重启）、池的状态显示、
  工具 id 折叠碰撞检测、子代理会话与主会话共用进程（子代理起自己的）。
- macOS 的沙盒只收写（sandbox-exec 的那一版），和脚本、命令一样。
