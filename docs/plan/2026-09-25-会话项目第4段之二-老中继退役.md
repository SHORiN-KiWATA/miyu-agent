## 现状（核查结论摘要）
子代理 09-18 起是一条会话，但 daemon 还把子会话的事件翻成老标记串（`subagent_host.rs::relay_child_events`，
`__subagent_reasoning__` / `__subtool_call__` / `__subagent_metric__` / `__subagent_session__` ……），经
`SubagentProgressSink = Fn(String)` 送出去：

- 前台子代理：送进父回合的工具进度通道（`tool.progress`）。引擎这边 `tee_subagent_trace` 顺手录一份，收尾时
  `tool_report.rs` 拼成 `sub_trace` 落库、并从 `__subagent_session__` 里取出 `child_session_id`。
  - 终端：`timeline/subagent.rs` 按标记攒一份子代理的内层日志，状态行的窥视、词元从它来，浮层画它。
  - 网页：`parseSubagentEvent` / `renderSubagentProgress` 把标记画成卡片里的 `.sub-blocks`，窥视也从它来。
- 后台子代理：送进任务日志桥（`subagent/log.rs`），写成模型 `job(action=status)` 读的任务日志，同时发任务进度
  （trace 环 → 终端浮层；`job.progress` → 网页任务条）和任务条上的词元。

## 目标
界面上子代理只剩三样：状态行 / 卡片上的窥视、词元、秒数（秒数本来就走工具计时），点它切进子会话看全程。
「把子会话再在父会话里画一遍」的整套拆掉。模型那边（任务日志、唤醒报告、追话）不变。

## 一、换（行为不变，先做、先验）
1. **引擎把标记收成状态**：前台子代理的进度不再原样转成 `tool.progress`。引擎里按标记算出三样——窥视（一行）、
   词元（显示串 + 数）、子会话 id——发一个新的 `AgentEvent::SubagentProgress`，daemon 发成 `subagent.progress`
   事件（带 `run_id`、`tool_id`、工具名）。标记协议留在引擎内部：中继照旧产标记，后台的日志桥照旧吃标记，
   界面不再见到标记。
2. **子会话 id 在拿到时就记进这一步**：引擎收到 `__subagent_session__` 就把它记进这次工具调用的记录，
   `ToolFlowCall.child_session_id` 不再靠 `sub_trace` 里翻。
3. **终端**：状态行的窥视、词元、会话链接改吃 `subagent.progress`（渲染器按工具名存一份子代理状态）。
4. **网页**：实时卡片的窥视、词元、会话链接改吃 `subagent.progress`；后台子代理的任务条那一行点下去打开
   子会话（和终端口径 6 一致），不再原地展开内层过程。

走查：终端 `subagent_visit.py`、`bg_visit_midturn.py`（三档）、`strip_keys.py`；网页 `webui-subagent/run.py`
（窥视有字、词元有数、点得进去、没有标记漏出）。

  `sub_trace` 组装（落库字段 `sub_trace` 与反序列化留着，老回合照旧读得出）。
