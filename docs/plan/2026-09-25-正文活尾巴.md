# 正文活尾巴（09-25）

来源：opencode v2 调研 3.5 第 5 条，工作安排第二节第 3 小节。分支 `worktree-reply-live-tail-2026-09-25`，从 main 8c18c5d5 开。

## 现象与根因
- 终端里正文按整行落：`MarkdownStreamRenderer::push` 攒到换行才吐。代码块要等闭合的围栏，表格要攒够三行，块级公式要等收尾定界符。
- 于是长代码块（或者一段很长、迟迟不换行的话）流着的时候，正文区一动不动，写完才一口气出来。思考早就有滚动窗，正文没有。
- 网页不受影响：`appendAssistantDelta` 每帧重渲，没闭合的围栏自动补上。这一项只管终端。

## 用户拍板（09-25）
- 覆盖所有终端形态：全屏、非全屏、shell hook、单次 `miyu "…"`、唤醒跟进、daemon 回写，和思考滚动窗覆盖的范围一样。管道、`--plain` 不变。
- 没闭合的代码块在临时区里和最终一个样子：带高亮和框，只露最后几行，框宽照整块算。mermaid 与公式先露源码，闭合后再出图。
- 行数跟思考滚动窗共用 `display.thinking_scroll_lines`（默认 10），再多也不超过活动区放得下的行数。

## 做法
- **活动区画板**（`render/live_area.rs`）：从转轮里抽出来的公共部件，转轮和正文尾巴共用。
  - 画一帧、按行比对着改、就地交接、擦掉，都在这里。
  - 点不开的面直接对终端上移、清行、重写。
  - 全屏发锚点标记（`LIVE_REWIND_MARKER` / `LIVE_END_MARKER`）。尾巴的行里有正文折行标记，行号对不上缓冲的逻辑行，所以尾巴整段重写（`Rewrite::Whole`）。没变的行缓冲会还回旧版本号，画面层照样跳过。
  - `wait_spinner.rs` 1006 → 720 行，字节零变化（hosts 892 条含金样全绿）。
- **预览**（`MarkdownStreamRenderer::pending_preview`）：没有副作用，不画 mermaid 图、不出公式图片、不动任何状态。
  - 半行：按一行正文渲。
  - 没闭合的代码块：`render_code_block_tail`，和 `render_code_block` 共用抬头与框宽，只渲最后几行，整块露得下才带抬头。
  - 公式：照原样露。
  - 进行中的表格那一行：按表格行渲（同一套列宽）。
  - 还没定下来是不是表格的几行：按普通行渲。
  - 超长的一行只看最后 8K 字（`PREVIEW_LINE_CHARS`），防每拍整段重渲把一个核吃满。
- **正文尾巴**（`stream/reply_tail.rs`）：
  - 每一拍（`tick_spinner`）画：正文流着、没有转轮时，指纹没变就不重算。
  - 一截字至少搁了一拍（40ms）还没落下才露出来：流得快的行照旧直接落下，不闪一下；不 tick 的用例（金样）字节不变。
  - 有整行落下时，同一帧（同步输出块）里擦掉、写正文、接着画剩下的那一截。
  - 擦除点：起转轮之前（四处创建点）、半行冲出去之前（`end_active_stream_line`）、`stop_waiting`（原来的只停转轮那一半改名 `stop_spinner`，`write_chunk` 的正文路径只停转轮、留着尾巴）、回合收尾、Drop。
  - 折行：全屏按正文那套缩进折（和落下之后一个样子）；静态面按终端宽度减一折好，不留软折行。

## 已知局限
- 静态面的尾巴按「终端宽度减一」折，落下时交给终端按整宽折，长行的换行点可能差一列。只在那一截落下的一瞬间看得出。
- 超过 8K 字的一行，预览只露最后那部分的折法，和落下时的折点可能不一样。
- 插话、转轮、工具调用一来，尾巴先擦掉，半行当场落下（和原来一样），不等写完。
