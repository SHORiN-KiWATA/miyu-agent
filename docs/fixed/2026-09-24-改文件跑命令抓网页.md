# 改文件、跑命令、抓网页的几处缺陷（09-24）

对照 opencode v2 时查出（调研 B2、B8、B10、B11 与两处小项，`~/Documents/MiyuPlan/2026-09-24-opencode-v2-deep-study.md`）。

## B2 edit 改完文件变 0600、软链被换成普通文件
- **根因**：`patch_preview::write_with_patch_preview` 先 `NamedTempFile::new_in` 再 `persist`（rename）。tempfile 3.27 在 Unix 上默认用 0o600 建文件，rename 之后目标就是 0600。路径没解析软链，rename 把软链本身替换掉了。
- **影响**：0755 的脚本改一次就丢执行位；dotfiles 这类软链被断开。git 只区分 644 和 755，所以 644 变 600 在 diff 里看不出来。
- **修法**：仍然原子写。
  - 目标是软链时写到它指向的文件，解析出来的目标要再过一遍 `sandbox::guard_write`。否则项目里一个指向沙盒外的软链，就能用来往外写。
  - 临时文件按 0666 创建，由 umask 收窄；已有文件改回它原来的权限位。
- 没处理：硬链接。rename 仍会让其余链接指向旧内容。原子写和保住 inode 只能二选一，这里保原子写。

## B11 补丁删除绕过回收站
- `Delete File` 直接调用 `remove_file`，和 rm 拦截、`trash_path`「删除必须能挽回」的原则不一致。
- 修法：文件系统里的删除改走 `trash::delete`；artifact 仍然直接删，kb 走知识库自己的路径，两者都不变。测试构建里走 `apply_patch/test_support.rs` 的假回收站（记下路径、直接删掉），不往开发者的真回收站里扔临时文件。

## B10 补丁匹配
- **歧义误报**：歧义判断从命中处往后用全部四档（Exact / TrimEnd / Trim / Normalize）再搜一遍。精确匹配明明唯一，只要后面有一处只差缩进的同样文本，就会误报「matches multiple locations」。改成只在命中的那一档里数。
- **各块不按顺序定位**：原来每块都从文件开头找。改成：从头找会歧义时，取上一块改完之后唯一的那一处（补丁里的块按文件顺序写）。匹配唯一时照旧从头找，所以乱序写的补丁不受影响。
  - opencode 是每块一律从上一块的结尾往后找；那样对乱序补丁会静默改错位置，这里没照搬。
- **报错**：写明「hunk k of n, starting at `首行`」；前缀从已经不存在的工具名 `apply_patch verification failed` 改成 `patch verification failed`。多文件补丁写到一半失败时，列出已经写进去的文件。
- **归一化**：补上 U+2212（负号）、U+2002–200A、U+202F、U+3000（各种空格）。

## B8 run_command 超时丢掉已有输出；截断后全文不落盘
- **根因**：超时分支直接 `return Err(timeout.error())`，读输出的 future 连同它手里的缓冲一起被丢掉，模型只拿到一句「超时」。超长输出只留末尾两万字，全文不落盘。
- **修法**：
  - 输出边读边写进 future 之外的共享缓冲（`OutputSink`）；超时时把已读到的部分截到末尾两万字，附在超时报错里。
  - 输出被截断时，把全文（8 MB 上限内）存进 `~/.miyu/cache/command-output/`，结果末尾写 `[full output saved to <path>]`。每次存盘时顺手清掉 7 天前的旧文件。

## 两处小项
- **web_fetch 拒收非文本**：Content-Type 既不是 text/*，也不是 JSON、XML、JS、YAML 一类时，直接报错并指路，让模型用 run_command 下载后再看。原来会把 PDF、图片按 UTF-8 硬解成乱码塞进上下文。
- **read 去掉 JSON 外壳**：输出改成纯文本，第一行是 `[路径 · lines a-b · more below, continue with offset=N]` 或 `· end]`，下面是带行号的正文；目录同理。原来正文塞在 JSON 字符串里，每个换行、引号都要转义，实测多一成多 token。旧回合里的 JSON 形态照旧逐字节回放；全仓只有一条单测在解析旧格式，已经改掉。
