## 根因：回放不是原样重放

回放一个历史回合用的是 tool_flow（只记工具轮）+ followups（不记位置）+ 流水账拼出来的，
不是活体发过的那串消息。轮里只要有工具轮以外的东西，拼出来的顺序就和活体不一样，下一轮第一条
请求在这一轮的起点分叉：

1. **被打断的轮**：`interrupted_turn_replay_messages` 把 `<interrupted-turn-recovery>` 插在该轮
   化石之后、第一个工具调用之前，整轮再从流水账拼。库里坐实两例（分叉下标正好是该轮第一个工具
   调用的位置），会话 A 的 09:53/09:56/10:17/10:24 四次改写前一轮都是打断。
2. **轮中插话**（模型跑工具时用户又发一句）：回放把插话放在所有工具轮前面，活体是插在第 k 轮后。
   还多补一条活体里没有的「插话前正文」（那段正文其实在 assistant(tc) 里）。会话 A 的 10:01
   （丢 57 万，分叉点在第 1309 条、上游只命中 1152 token）与 10:12 两次。
3. **连续两轮相同的工具调用**：`replay_rounds` 回放时折掉重复轮，活体两轮都发过。注释说「一次性
   冷启动」，实际每出现一次断一次。
4. **goal 收尾通知**：轮中插的 turn_context 不进 tool_flow，回放缺这一条。

分叉一次的代价不可预测：上游只能命中它存过的前缀，10:01 那次分叉点很靠后，却几乎整段没命中。

## 改法

- `derive_tool_flow` 把工具轮以外的活体消息按位置记进 flow：`ToolFlowRound.after`（这一轮结果之后）
  与第一轮的 `before`，并打 `interleaved` 标记。纯文本原样存字节；带图的插话只记排队消息 id
  （`FlowMessage::Followup`，回放按排队消息重建，不把 base64 抄第二份）；工具结果的媒体伴随消息
  不抄（`ChatMessage.media_companion`，回放由 turn_inline_media 重建）。**不加迁移列**：JSON 里多
  几个可缺省字段，老构建读到忽略、照老路子回放，回退不会打不开库。
- 回放（`push_tool_flow`，完成轮与打断轮共用）：轮间消息原样放回；新记录不再另拼 followups。
- 打断轮（新模块 `agent/interrupted_replay.rs`）：已落盘的工具轮照完成轮原样回放 → 检查点之后
  那一截从流水账补 → 恢复提示放到最后。老记录与重做分支走老路子，字节不变。
- 检查点挪到 goal 通知与插话并入**之后**（`after_tool_round` 末尾），另两处并入插话的路径
  （被超越、插话前已有正文）也补检查点。
- 复读轮折叠挪到压缩那一刻（`fold_repeated_rounds`，同 09-23 剪枝挪位的道理），折掉那轮后面的
  轮间消息并到留下的那轮。

## 取证补强

## x-opencode-request A/B（用户要求当天出结论）

Miyu 每个 HTTP 请求换一个 id，opencode 官方客户端一轮用一个。288 次请求（两组交替各 18 轮 ×8 步，
deepseek-v4.1-flash via opencodego）：两组各 126 次都吃满上一请求整段，缺的只是末尾不满两块
（64 token 一块）的零头，没有差别。网关源码（opencode `packages/console/app/src/routes/zen/util/handler.ts`）
也对得上：粘性路由只看 `x-opencode-session`，`x-opencode-request` 只进日志。结论：不改。
生产里那 2% 的上游丢缓存是成段出现的（09-24 02:00–02:40 两个会话同时卡在 29312/69120），
网关源码里供应商会因 TPS 偏低、预算、失败重试而换掉，多半是这个（未坐实），我们这边控制不了。

## 追记一：回合尾巴被记两遍（09-24 晚，做 C3 时实测抓到）

- 现象：C3 的黑盒测具里，修前二进制（= 已合 main 的上面这版）在「回合尾巴非空的工具轮」之后
  纯追加为假。桩端点逐字节对比：活体第 N 条是调工具的 assistant，回放在同一位置多出一份尾巴。
- 根因：`derive_tool_flow` 从 `replay_start` 扫起，而 `replay_start` 取在回合尾巴追加**之前**。
  上面的改法让它把工具轮以外的消息按位置记进 flow，尾巴也就被当成「第一轮之前并进来的消息」
  记进了 `before`：回放时尾巴随化石放一次、随 `before` 再放一次。
- 前面没抓到：测具里的回合尾巴全是空的（`replay_prefix.rs` 的桩回合没有尾巴，真模型套件关了
  记忆、dev 模式没有表情包提醒、终端回合没有传输上下文）。生产上尾巴非空很常见：联想记忆、
  QQ 上下文、网页 artifact 清单。
- 修法：化石与工具流共用一个判据 `is_turn_tail_message`（瞬态 + 纯文本），化石取到哪，工具流就从
  哪记起，两段正好拼回活体。redo 两条路径同理（化石起点与 `replay_start` 之间也全是尾巴块）。
- 影响面：main 未推送。本机生产 daemon 17:30 起跑的是含回归的构建，17:50 拷副本（连 WAL）查过，
  新格式工具轮 0 条，没有写坏的记录，不做旧数据修复。
- 验证：`replay_prefix.rs` 新增完成轮 / 插话轮 / 打断轮各一条「带尾巴」用例，修前三条都红在
  「活体 assistant 调工具，回放多一份尾巴」。
