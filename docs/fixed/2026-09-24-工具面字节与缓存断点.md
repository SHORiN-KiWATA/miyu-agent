# 工具面字节中途变化，Anthropic 与 OpenAI 直连没有缓存提示（09-24）

对照 opencode v2 时查出（调研 B5、B13 与两处缓存小项，`~/Documents/MiyuPlan/2026-09-24-opencode-v2-deep-study.md`）。tools 排在前缀最前面，它一变，连 system 在内整段缓存都作废。

## B5 到工具轮数上限时整份不带 tools
- **根因**：`round_tool_definitions` 在「轮数用完」和「复读保险丝熔断」时都一个工具都不给。最后那一轮于是整段不命中，偏偏是上下文最大的时候（QQ 平台回合默认上限 32）。v7 计划本来写的是「保持 tools 只加尾部提示」，没有落地。
- **修法**：两种上限分开。
  - 复读保险丝熔断是端点故障态，照旧收走工具逼模型成文（08-24 的设计，不动）。
  - 轮数用完：照带同一份工具，这一轮的 client 用 `with_tool_choice_none()`。chat 与 Responses 写 `"tool_choice": "none"`，Anthropic 写 `{"type": "none"}`；模型硬调的工具调用照旧被 `finish_at_tool_limit` 丢掉。
  - 网关报 `tool_choice` 不认（400/422 且报文点名这个字段）时，退回原来那种不带工具的请求重发一次。
  - 中转线（claude-code、codex、agy、codebuddy）的工具循环在 CLI 里，不涉及。
- **待实测**：`tool_choice` 会不会改变网关渲染出来的前缀，要看真实请求的 cache-usage 才知道。最坏情况和原来一样是整段不命中。

## B13 技能目录一变，tools 就变
- **根因**：默认加载模式是 full（09-01 定稿），`load_skill` 的完整描述里拼着整份技能目录，每轮按指纹热刷新、一变就重新注册。技能一增删或改描述（包括回合中途用 manage_skill 发布），所有在线会话下一轮整段不命中。
- **修法（09-24，已被 09-25 的做法取代）**：按会话冻结。
  - `round_tool_definitions` 在 full 模式下，把发出去的 `load_skill` 描述换成本会话冻结的那份。
  - 冻结点是「最近一份摘要的轮 id」：同一个压缩周期里一直发第一次发出去的那份；压缩之后前缀本来就断了一次，这时换成当时的目录。
  - 存在 `app_state`（`skill_catalog:<会话 id>`），不加迁移。/reset 删掉本会话的快照；删会话和 /reset 时清掉所有会话已不存在的快照，子代理会话留下的也在这里清。
  - 注册表照旧热刷新，新发布的技能照样能按名字加载。
- **09-25 复查出的漏洞**：stub 模式没冻结（`load_skill` 常驻，stub 模式照样发整份描述，上面「只露第一行」是错的）；压缩摘要请求与上下文估算用的是没冻结的那份；模型始终不知道目录变了（新技能要到压缩后才列出来，删掉的还列着、加载时报找不到）；manage_skill 回执还写着「下一轮工具就刷新」。
- **09-25 的做法（用户拍板「整份搬出描述，放进回合尾巴」）**：`load_skill` 描述改成常量（真相源回到 `descriptions/load_skill.json`），目录作为指令源随回合尾巴发（`<available-skills>`），变了再发一整份、一件不剩时补一句空目录；按会话冻结那一套连同 `app_state` 快照一起撤掉。见 `docs/plan/2026-09-25-指令源统一抽象.md`。

## 两处缓存小项（只影响直连用户）
- **Anthropic 直连没有任何 `cache_control`**：官方接口不打标记就完全不缓存（原来是「有数据再做」的有意延期）。发送前在最后一件工具、system（改成文本块数组）、对话尾巴各打一个 `ephemeral` 断点，共 3 个，上限是 4 个。思考块不打；用户在 extra_body 里自己配了 `cache_control` 的请求原样不动。
- **prompt_cache_key**：只对 OpenAI 官方端点（`api.openai.com`）发，值是会话 id；保温请求用同一个键。别的网关不一定认这个字段，严格的会整条请求 400，所以不发。
