# 15 · 扩展指南

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

Miyu 提供了五层扩展入口，从“完全不用写代码”到“写协议适配器”，按成本排序。

## 1. 不改代码的扩展（推荐先试）

| 想加什么 | 怎么做 |
|---|---|
| 新知识 | `miyu kb add`，或直接让 AI 用 `edit` 往 `kb:` 命名空间写文件 |
| 新流程/能力 | 让 AI `manage_skill`（action=create → 草稿 → action=publish），按 `src/personas/default/skills/skill-creator/SKILL.md` 规范 |
| 新脚本工具 | 让 AI 按 `script-creator` 技能写脚本（头部注释即契约），`manage_script`（action=register，path 给任意路径）自动复制进脚本目录；接口见 `docs/scripts/README.md` |
| 新表情 | 给 AI 图片路径，`manage_meme`（action=add）自动识图入库 |
| 新人格 | `miyu config` → 自定义提示词 → 新建 persona |
| 新主题 | 把 matugen 生成的 `webui-theme.css` 放到 `~/.miyu/config/webui-theme.css` |
| 新 MCP 工具 | 配置 `mcp.servers`（stdio server），工具自动注册；要查宿主信息加 `capabilities`（见 docs/interfaces/host-capabilities.md） |

## 1.5 打包与安装扩展(`miyu pm`)

> 暂不公开:`pm` 已从 `miyu --help` 和补全里隐藏,接口还没定稿。显式 `miyu pm …` / `miyupm …` 行为不变,已装的包照旧可用。

一个包 = 一个仓库(GitHub)或本地目录,根上一份 `miyu-package.toml`:

```toml
[package]
name = "bangumi-tools"          # 小写字母、数字、- _;2–64 位
version = "1.0.0"
description = "番组日历与搜索"
kind = "extension"              # extension(缺省)或 persona
requires-miyu = ">=0.5.0"       # 可选,只支持 >=
requires-contracts = { scripts = 1, skills = 1 }   # 可选:按哪版契约写(见 docs/interfaces/compatibility.md),宿主不认识或版本更高就拒装
requires-capabilities = []      # 可选:需要宿主授予的能力;今天宿主不向包授予任何能力,非空即拒装

[install]                       # 都可省,下面是缺省值
scripts = ["scripts/*"]         # 脚本文件(头部契约见 docs/scripts/README.md)
skills = ["skills/*"]           # 技能目录,每个里面要有 SKILL.md
persona = "persona"             # kind = persona 时的人格目录
```

- `extension` 包的脚本装到 `extensions/scripts/`、技能装到 `extensions/skills/<名>/`,所有人格可见。
- `persona` 包:`persona/persona.md` → `data/prompts/<包名>.md`(人格提示词),可选 `persona.json`(头像/看板等元数据,路径相对 `persona-avatars/`)、`persona.toml`(启用集)→ `personas/<scope>/persona.toml`、`assets/` → `persona-avatars/<包名>/`;包里的脚本与技能只给这个人格(`extensions/{scripts,skills}/personas/<scope>/`)。
- 命令:`miyu pm install <包名|owner/repo[@ref]|GitHub URL|本地目录>`(装前摊开文件清单再确认,`-y` 跳过)、`remove`、`upgrade`(commit 或内容指纹没变就不动)、`search`、`list`、`tap add|remove|list`。`miyupm` 是同一套(argv[0] 识别,打包做个符号链接)。
- 索引:tap 是一个 GitHub 仓库,根上 `index.json`:`{"packages": {"bangumi-tools": {"repo": "owner/repo", "description": "…", "kind": "extension"}}}`。官方 tap `SHORiN-KiWATA/miyu-packages` 缺省在列。
- 锁文件 `extensions/pm/lock.json` 记来源、commit、版本、装进来的每个文件与内容指纹;卸载按它删,目标文件被别的包占着或不是 pm 装的会拒(`--force` 覆盖)。只往 `extensions/`、`personas/`(以及人格的 `data/prompts`、`data/persona-avatars`)写。装完通知 daemon 重载;脚本目录变了下一回合自动重扫。
- 不做:签名、沙盒、二进制包、MCP 配置片段(这些留给以后)。

## 2. 新增一个 Rust 内置工具 / 内置插件

一个内置插件 = 一个注册函数 + 若干工具描述 JSON + 登记表里的一行。09-16 起两张登记表
(`crates/miyu-base/src/config/builtin_plugins.rs` 的描述符、`crates/miyu-engine/src/tools/builtin_plugins.rs` 的注册函数)按 id
对齐,`PLUGIN_IDS`、引导里的开关名单、中文名全部从表派生;漏了任何一处,
`registrars_cover_every_builtin` / `derived_lists_match_the_former_hand_written_tables` 报红。

步骤:

1. 新建 `crates/miyu-engine/src/tools/my_plugin.rs`,写 `pub fn register(registry: &mut ToolRegistry, …)`:

```rust
pub fn register(registry: &mut ToolRegistry, config: AppConfig) {
    registry.register(
        ToolSpec::new(
            "my_tool_name",
            "占位描述(注册时被 JSON 整体覆盖)",
            serde_json::json!({ "type": "object", "properties": {} }),
            |args| async move { Ok("ok".to_string()) },
        )
        .writes(), // 只读就不要;presentation() 是第三档
    );
}
```

2. `crates/miyu-engine/src/tools/mod.rs` 顶部加 `mod my_plugin;`。
3. 新建 `src/tools/descriptions/my_tool_name.json`(`name / display_name / description /
   parameters / always_loaded / load_policy / groups / timeout_seconds / trust`),并在
   `crates/miyu-engine/src/tools/tool_descriptions.rs` 的宏里加 `include_str!("descriptions/my_tool_name.json")`;
   再在 `crates/miyu-engine/src/tools/mod.rs::builtin_readable_tool_name` 加一个中文显示名(界面上显示的名字,
   测试 `readable_names_cover_all_built_in_tools_and_groups` 钉着,漏了报红)。
4. **`crates/miyu-base/src/config/builtin_plugins.rs` 的 `BUILTIN_PLUGINS` 加一行**:id、`PluginKind::Builtin`、
   中文名与一句话说明、要不要在引导里给开关、机器开关(`installed: fn(&AppConfig) -> bool`,
   常开写 `always`)。这一行就是 persona.toml 里的名字、引导页的开关、`plugin_label` 的来源。
5. **`crates/miyu-engine/src/tools/builtin_plugins.rs` 的 `REGISTRARS` 加一行**:同一个 id → 你的注册函数;
   子代理不该拿到的(如记账)标 `after_subagent_snapshot: true`。
6. 若要配置开关,在 `crates/miyu-base/src/config/tool_plugins.rs` 的 `PluginsConfig` 加字段(默认值、校验)、
   WebUI `web/settings-schema.js` 与 TUI 表单;第 4 步的 `installed` 读它。
7. 跑 `cargo test --lib -- config::builtin_plugins tools::builtin_plugins tools::shape_tests`,
   重生成 `src/tools/fixtures/registry-shapes.json`(`write_registry_shape_fixture`,ignored)。

移除一个插件:反着做,再把 id 加进 `persona_manifest.rs` 的 `RETIRED_PLUGIN_IDS`——存量
persona.toml 里还写着它,不能因为删插件把人格锁在门外。

`files`(core 开关)、`scripts` / `mcp`(外装件接入机制)不走注册函数表,由 `compose` 显式处理。

**测试夹具放哪**:只给测试用的构造函数 / 探针方法 / 假对象,一律放同模块的 `test_support.rs`
(`#[cfg(test)] mod test_support;` + `use test_support::*;` 再导出),别在生产文件里写 `#[cfg(test)] fn`——
拆 crate 后跨 crate 看不见,读代码也不用跳过它们(09-16 搬家 110 项后的约定)。

**关键坑**:

- 描述以 JSON 为真相源,Rust 里的 `description` 只是占位(例外:`load_skill` 的描述是运行时拼的动态目录)。
- 权限只由 `.writes()` / `.presentation()` 决定,JSON 的 permission 字段不生效。
- 懒加载 stub 会以"一句话摘要 + 宽松参数壳"常驻;完整 schema 通过 `load_tools` 返回,不要为了显示完整参数把工具设成 always_loaded(会破坏前缀缓存)。
- **编辑/读取类能力优先并入 `edit` / `read` 的命名空间**(裸路径=文件系统、`artifact:`=Artifact 库、`kb:`=知识库),别为一个新存储再开一套读写工具。
- 改了描述/schema/工具名 = 工具面字节变 = 一次缓存冷启动;按 AGENTS 的规矩手测两轮 cache-usage。

## 3. 新增一个用户技能

直接看 `src/personas/default/skills/skill-creator/SKILL.md`。核心规范：

- frontmatter 必须有 `name`（小写 ASCII/数字/连字符）和 `description`（触发条件写清楚）。
- `allowed-tools` 只是兼容性元数据，**不授权限**。
- 使用 `manage_skill`（action=create/update）生成草稿，用 `edit` 写文件，最后 `manage_skill`（action=publish）原子发布。
- 脚本是资源，发布 skill 不会自动把脚本注册为工具。

## 4. 新增通讯平台（PlatformAdapter）

Miyu 的平台核心是通用的，OneBot 只是第一个实现。步骤：

1. 新建 `src/platforms/<name>.rs`，在 `platforms/mod.rs` 声明模块。
2. 实现 `PlatformAdapter` trait（`platforms/types.rs:404-508`）：
   - 必须实现 `send` 和 `bot_display_name`；
   - 按能力覆盖 `message_info`、`fetch_platform_file`、`group_members`、`set_group_ban`、`delete_message` 等；不覆盖有明确的 not-supported 错误。
3. 把协议入站事件转成 `PlatformInboundEvent`（`types.rs:176-216`），填 platform/account/conversation/position/ingress_order/text/media。
4. 用 `resolve_platform_session`（`platforms/mod.rs:1564`）拿会话，再调 `run_platform_turn`（`mod.rs:2094`）；排队/抢占用 `PlatformRuntime::acquire_session_turn/preempt_session_turns`。
5. 出站消息用 `OutboundSegment::{Markdown,Text,Mention,ImageBytes,ImagePath,FilePath}` 和 `OutboundBody::{Segments,Forward}`，按你平台的能力序列化。
6. 新平台命令在 `platforms/commands.rs` 加描述符、解析与权限；新平台工具在 `platforms/tool.rs` 注册。
7. 配置：在 `config.rs` 的 `PlatformsConfig` 加平台块；平台插件通过通用 `PlatformPlugin` trait 可复用。

注意当前仍有少量 OneBot 特化：`access_control.rs` 的 onebot 平台名、`file_reader.rs` 的 `platform_files/qq` 路径、`qq_mention_users` 等。做多平台支持时需要参数化。

## 5. 新增平台插件

插件 trait 在 `platforms/plugins/mod.rs:257-407`：

```rust
#[async_trait]
impl PlatformPlugin for MyPlugin {
    fn descriptor(&self) -> PluginDescriptor {
        PluginDescriptor { id: "my_plugin", priority: 150, default_enabled: true }
    }
    // 按需覆盖 hook：
    // observe_ingress / handle_command / register_tools / preempt_inbound
    // turn_started / observe_inbound / decide_trigger / before_turn
    // before_send / after_send / after_session_reset / after_persona_reset ...
}
```

然后在 `built_in()` 注册，并加配置块 `platforms.qq.plugins.<id>`。

Hook 契约：

- `memory_content` 插件禁止改；`system_context` 必须字节稳定，动态内容走 `turn_system_context`。
- `before_send` 默认 `PreparedSend::unchanged`；改过 metadata 会自动补 fallback；转图/转发类插件应显式给 `fallback=原消息`。
- 固定输出可用 `send_fixed_tool_output` 旁路整个插件链，并压制后续模型回复。

## 6. 新增 LLM 供应商协议/能力

- 协议类型：`ProviderProtocol`（`llm/openai_compatible.rs:370`），已有 chat / responses / anthropic。
- 新协议要扩展：`from_provider`、`effective_protocol`、`chat_stream_single`、请求结构、SSE 解析、usage 归一化。
- 新 capability：`provider_capabilities.rs` 只持久化 false 条目；运行时能力位在客户端结构里建模。
- 新 usage 字段：`Usage` → `normalize_cache_fields` → cache log / usage 明细同步。
- 错误分类/冷却：`classify_provider_error_body`、`cooldown_for_status/error`、`endpoint_failover_allowed`、`same_endpoint_retry_allowed`。

## 7. 新增配置项

1. `config.rs` 的结构体加 `#[serde(default...)]` 字段。
2. `Default` 或 `default_xxx()` 给默认值。
3. `validate()` 加校验。
4. 需要 normalize/迁移时在 `migrate`/`normalize_*` 处理。
5. TUI：主菜单入口、插件字段（`config_tui.rs` 的 `plugin_fields`/`apply_plugin_fields`）、或全局设置表单（`edit_settings` 字段只能**追加末尾**，有 debug_assert 锁数量）。
6. 加测试。

## 9. 改 WebUI

- 静态文件 `web/index.html`、`web/styles.css`、`web/app.js` 通过 `include_str!/include_bytes!` 嵌入，**改完必须重新 build**。
- 后端新路由：`web.rs` 的 router（3736 附近）；读接口 `require_auth`，写接口 `require_mutation`。
- 新 SSE 事件：`RunEventMapper` 映射，事件必须带 run_id，否则被过滤。
- 前端主题：在 `styles.css` 加 `body[data-theme="..."]` MD3 token 块，并同步主题按钮。
- CSP 是 `script-src 'self'; style-src 'self'`，内联脚本/样式会被拦截。
