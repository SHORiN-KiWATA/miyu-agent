# Miyu 0.6.2 完整更新记录

按开发期逐条记录整理，含根因与实测数据。Release 正文取短版 `release-notes.md`。

## 新增

- 群里她能主动把内容渲成图片发出来了。以前「长文转图」只在她一条回复太长时自动触发，她自己说了不算；现在她可以挑一段内容直接出成成品图——表格、结构化说明，以及 **mermaid 流程图**（画进正文同一张图里，不是单独一张）。也可以直接给一个 `.md` 文件让她画，文件内容不会占用对话额度。图只生成不自动发，发哪张由她定。顺带修掉一个老毛病：以前在群里画流程图，出来的是一张 mermaid 源码的截图。需要重启 daemon。

- 她现在查得到「**这条对话**烧了多少」了。以前 footer 上那几个数是画给你看的，模型手上一个字都没有——你问她「我们这个会话用了多少 token」，她只能查到整个 Miyu 的总账。新增工具 `query_session_token_usage`：当前上下文占了窗口多少、这条会话累计烧了多少（含它派出去的子代理）、聊了几轮。顺带把原来那件 `query_token_usage` 改名成 `query_system_token_usage`，名字直接说清楚问的是「整个 Miyu」还是「这条对话」，两件工具的抬头也分成「Token 消耗 · 全局 · 近一天」和「Token 消耗 · 本会话」。**注意**：改名之后，老会话历史里那些按旧名的调用记录会变成未知工具，她照着模仿会撞一次错再改口，新会话不受影响。另外这两件工具（以及改名前那件）在终端时间线上一直显示成裸英文 id，现在都有中文名了。需要重启 daemon。

- QQ 的「私聊/群聊专属配置」多了一条**概率主动回复抽样概率**，可以给某个群或某个人单独定一个话痨程度，覆盖插件设置里那个全局概率。填 0 到 1 之间的小数（和插件设置同一个口径），留空就继续跟着插件设置走。它和上面那个开关是两件事：开关管这个会话做不做概率抽样，这一项管抽中的概率有多大；开关关掉时这一项不起作用。同时把原来的「概率主动回复」改名为「开关概率主动回复」，免得和新加的这项混淆。终端配置界面和控制台设置页都有。需要重启 daemon。

- 内置表情库新增两张：《猫和老鼠》里两只猫仰头狂笑（别人讲了好笑的事、看到翻车现场、想跟着一起笑或明着嘲笑时用），以及「我他妈直接当群主」（群里聊到群主／管理员权限、有人起哄推你上位、想开玩笑宣布「这事我说了算」时用）。内置库现在共 38 张。

- 重型脚本改由技能带路：脚本住进 `personas/<人格>/skills/<技能名>/scripts/` 就不再进模型的常驻工具清单（照常注册、可经工具桥调用），由技能正文带路；住别处的脚本照旧进面。判据是「住在哪」，不再是脚本头部的一行声明。

- 发布构建不再每次重下同一批锁定归档。同样那 190MB 语音模型加上 sherpa-onnx、onnxruntime、维基快照，以前每发一个版本都要从头拉一遍——下载缓存的参数一直存在，只是发布流程从没传过它，而且缓存只读不写。现在默认用 `~/.cache/miyu-release/downloads`，可以用 `--download-cache` 改；哈希校验两头都做，缓存被改过照样会被拒绝。

## 变更

- 空会话的上下文占用降了约两成。工具清单是每轮都要重发的那一份，以前它自己就吃掉 15.8k token（空会话 footer 里 18k 的绝大部分）。这次把每件工具的说明和参数 schema 逐个重写：功能一项没减，只是把「调用之后才用得上」的东西（字段含义、分页边界、输出格式细节）从常驻说明里挪进工具自己的返回。本机实测空会话 18,325 → 12,964 token，同一个问题发给模型，供应商报的输入 token 从 21,105 降到 15,133。长会话因此能多装下四五轮对话再触发压缩。

- 表情包够表达意思的时候，她可以只发表情、一个字都不说了。以前无论如何都会再配一句话，而真人有时就是甩个表情完事。现在她自己判断：表情已经说清了就只发表情，还有话要说（比如真的在追问）照旧配字。需要重启 daemon。

- 通讯平台上的表情包不再跟文字挤在同一条消息里。真人不会把一句话和一个表情塞进一条发，所以现在拆成两条：先后顺序随机（有时先说话再补表情，有时先甩表情再解释），中间停顿也是随机的 0.4–1.2 秒。表情那条永远不带引用和艾特——引用只挂在说话那条上，不会看着像回了两遍。生成的图片不受影响，仍然跟正文同条发（「给你画了这个」配图在一条里读着才正常）。

- 表情包发出去的尺寸跟 QQ 自带表情一样了。同一张图在 QQ 里当表情发是小的、当图片发要大一倍多，而 Miyu 发出来一直是大的那一档，看着突兀。现在发表情包时会标明「这是表情」，由 QQ 按表情的尺寸显示。图片本身没有被重新压缩，所以画质不变、动图照常会动，也不额外占用任何性能。生成的图片、图表不受影响，仍按图片的尺寸显示。

- 搜图不再自己把图发出去或贴出来。以前搜到几张就会**全部**自动发进 QQ／自动贴在终端里，哪怕她自己看完觉得不合格、另外做了更好的——09-21 有一次就这样一口气发了 5 张，其中 3 张是她正文里明说「一堆假透明」弃用掉的。现在这件工具只负责搜到并下载到本地，发哪几张由她挑：群里用发消息工具一次发完（配文跟图同一条），终端里用「显示图片」。顺带「显示图片」改成一次能打多张，不限张数。原来那两个配置项「自动预览」「默认预览数量」作废，留在配置文件里也不会报错。需要重启 daemon。

- 机票比价、酒店比价两件脚本改成「旅游攻略」技能的随附工具。它们的说明合计占 1.7k token，常驻一年也用不了几次；现在不再占常驻清单，聊到旅行、加载那份技能之后照常能用。

- 另有两件工具同样改成「用到时加载技能」：哔哩哔哩直播控制（开播是立刻公开并推送粉丝的动作，藏一层更安全）和 DeepSeek 服务状态查询。说「开个播」「改直播标题」「DeepSeek 挂了吗」照样能用，Miyu 会自己找到对应技能。

- 「管理脚本」「管理技能」两件工具改由既有的 script-creator / skill-creator 技能带路。它们是一周用不了一次的配置动作，说「把这个脚本注册成工具」照常能用，Miyu 会自己加载对应技能再执行。

- 换一个 Miyu 家目录不会再重下一遍语音模型。唤醒词、语音识别、断句这三份模型合计约 190MB，以前存在**每个家目录各自的** `state/models` 下，所以每开一个新家（换 `MIYU_HOME`、多用户、跑测试沙箱）就要重新下载一整份。现在改成机器级共享（`~/.cache/miyu/voice-models`），下一次就直接复用。**已经下过的人不受影响**：原来那份仍然排在最前面，不会重下也不会搬走。需要重启 daemon。

- 后台任务跑完的报告插进正在进行的回合时，长相变了。它以前是当成「你又说了一句话」处理的：画一条粉色的用户气泡，里面还带着内部抬头 `[后台任务完成]`，排队等待时还额外占一行「排队中」。现在是一条通知——这一轮先收成 `Worked for …`，底下报一行 `命令完成 <编号> · <任务名>`，再空一行接着说；排队等待期间它不再占气泡，被这一轮吃进去时才出现。

- 控制台里的流程图跟着主题走了。以前无论浅色深色，图都是一块白底的浅色图硬贴在页面上；现在底是透明的、线条和文字都用主题色，切主题图跟着变，壁纸配色（matugen）也吃得到。终端里的流程图底色也从刺眼的纯白换成了柔和的浅灰。控制台需要刷新一下页面。

- 群里发出来的成品图里，流程图不再是一块突兀的白方块了。正文是米色纸面，图却带着纯白底，一眼就看出是贴上去的。现在图的底色跟着页面主题走，换主题也跟着变。

- 默认的多模态模型从 `mimo-v2.5-free` 换成 `mimo-v2.6-flash-free`。这是「没有显式指定视觉供应商、也没配多模态模型池」时看图走的那个兜底模型，opencode Zen 上两个都还在，新的那个是更新的一代。**你自己配过多模态模型池的话不受影响**——兜底只在池子空着时才用到。

## 修复

- 用 opencode Zen 系的供应商（`opencode.ai/zen/...`）时，她读文件会一直失败，报「unknown tool: read_file」并反复重试。上个版本为了通过 Zen 的客户端识别，给发出去的工具名做了一层改名；改回来那一步用了一个早已废弃的旧工具名，于是她**正确**调用的读文件被改写成了一个不存在的名字——她每次都是对的，每次都被判错，而错误提示还在建议她用那个她本来就在用的名字，于是卡成死循环。跑命令不受影响，只有读文件坏。现在修好了，并加了检查：以后这张改名表里只要出现一个不存在的工具名，构建就会直接报错。需要重启 daemon。

- 同一个 Miyu 家目录不会再同时跑起两个后台进程。此前只要 `MIYU_HOME` 在一处设了、另一处没设（哪怕它指的就是默认的 `~/.miyu`），同一份数据就会被当成两套环境各起一个后台进程，连带各自拉起一个语音进程抢同一个麦克风，白占约 80MB 内存和 0.8% 的 CPU。现在后起的那个会主动让位；万一你两边的环境确实对不齐，命令行会直接说明哪个进程正占着、以及怎么把它交接过来，而不是卡在「启动超时」。

- 判断「是不是已经有 daemon 占着」不再会被一瞬间的误判带偏。那把锁以前只试一次：拿不到就当成 daemon 在跑。问题是检查「锁被占着没有」这件事本身也得先去拿一次锁再放掉，两边撞在同一微秒就会误判——后果是家目录搬迁或回滚**静默地什么都不做**，看起来像没生效。现在会连续观察一小段时间，期间只要有一刻拿得到就不算占用；真被 daemon 攥着的照旧判占用。拿得到的常路一次就返回，不慢。

- 终端里一轮对话以报错收场时，输入框下面那条状态栏右边的声波动画不会再卡住了。以前它会停在最后一帧不动，直到你按一下键才消失，看着像是还在跑。取消（Ctrl+C）那条路早就修过，报错这条漏了；这次连带把「连接断了、写不出去」之类的意外退出也一并兜住。换新的 miyu 后退出重进终端即可，不用重启 daemon。

- 回合被打断之后，它已经跑过的过程不再凭空消失。以前只有正常跑完的回合会留下回放用的快照，被打断的那种不留；而正文是从**最后一段**流水账里投影的，一轮里每被插一条跟进消息就切一段，于是前面几段说过的话、想过的东西、调过的工具全都看不见了，重开终端只剩一句「已中断」——尽管完整记录一直躺在库里。现在打断时也会存快照，投影也改成把所有段接起来。**你已有的会话不用做任何事**：以前被打断的那些轮，重开时会当场从库里的记录补回来。最常撞上这件事的其实是重启 daemon：上一个 daemon 跑到一半的回合会被新 daemon 判为中断，那条路一并修了。

- 关掉终端不再取消正在跟进的后台任务回合。自己发起的回合早就是「观众离席，戏照演」，而挂在后台任务唤醒轮上时，关掉终端会先发一条取消再退出。两条路现在语义一致。需要重启 daemon。

- 空会话里用鼠标选输入框的文字，不会再把左边那根竖线一起选走了。非空会话本来就正常——差别在于空会话的星空是画在输入框左边的，程序原来只认「竖线在行首」这一种情况。换新的 miyu 后退出重进终端即可。

- 鼠标移出终端窗口之后，那一下悬浮提亮不会再留在屏幕上了。终端不会告诉程序「指针离开了」——实测 kitty 在指针出窗口时连焦点事件都不发，只是从此不再报位置，所以那一行就一直亮着。现在按「最后一下落在屏幕最外一圈、随后短暂静默」判定指针已经出去，把提亮熄掉，约 0.12 秒。**指针停在正文当中不动不算**：那是悬着看，提亮照旧留着，停多久都不会灭。切到别的窗口（焦点真的变了）时也会立刻熄灭。换新的 miyu 后退出终端重进即可，不用重启 daemon。

- 设置里「启用的功能」那一页不再中英混杂。脚本和技能的说明以前直接摆的是写给模型看的那一份（恒英文），于是中文名后面跟着一长串英文。现在名字和说明各有「给模型」和「给人」两份，界面只读给人的那份；19 个自带脚本和 6 份技能都补了中文说明。

- 那一页按回车终于有反应了。脚本、技能、MCP 这几行没有设置页，以前按下去什么都不发生，底部却一直写着「⏎ 设置」。现在按回车看完整说明（表上那一列会按宽度截断），底部提示也跟着这一行变成「⏎ 详情」。

- 「旅游攻略规划」技能从加进来那天起就加载不了（漏了一处登记），现在修好了。顺带加了检查，以后再漏会在构建时直接报错。

- 记账工具不再声称每个账本都有「现金 / 电子支付 / 交通卡 / 信用卡 / 银行卡」——那是新建账本的默认账户，在你已有的账本上会让 Miyu 去用一个不存在的账户。现在它会直接从报错里读到你真实的账户名。

## 移除

- 删掉四件有等价替代的工具：查询进程占用、查询环境变量、查看系统信息、Fcitx5 Wiki 查询。前三件一条命令就能做，最后一件网络搜索够用。

- 删掉了「查询大模型 API 额度」这件内置工具。它只会查 DeepSeek 和 OpenRouter 两家，一个脚本工具就能替代，没必要为它常驻一份说明；设置里对应的页面一并移除，配置文件里的旧字段会被自动忽略。
